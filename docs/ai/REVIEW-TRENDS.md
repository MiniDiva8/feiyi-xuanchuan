# 活动复盘：录入数据变化与后续行动

在活动工作室「复盘与下一轮」点击「生成复盘」，最近两个有记录日期的曝光、收入、营销花费汇总变化会排在「观察事实」前面，列出日期、前后数值、差额和百分比，并在依据中给出字段和计算方式。某指标前值为0时只显示绝对变化，不计算百分比。曝光减少时，建议先核对发布作品、渠道和统计区间，再测试一个开场变量；收入变化时建议核对订单、退款和来源。建议是下一步核对与实验，不是已证实的原因。已有渠道总量也会显示，但不能直接比较不同渠道的优劣。

例如虚构测试数据：11月1日录入曝光100、11月2日录入曝光50，新的复盘会显示减少50、变化−50%，建议核对同口径后只调整一个开场，再录入下一次的曝光。须点击「生成复盘」生成新版本；旧复盘保持历史快照，不会自动更新。两条记录在同一天时，现有汇总只提供一个日期，无法推断哪一条先后，界面会提示补充不同日期的数据。

## 判断边界

- 仅比较最近两个有记录的日期，是按日期跨渠道的录入**合计**，不是任意两条原始记录或必然连续的两天；渠道、作品、天数、统计区间不同都可能造成变化。累计快照不能当作每日增量相加；比较之前须确认口径一致。
- 当前后端按日期仅传入曝光、收入、营销花费。观看/播放、阅读、互动、咨询、订单、报名等只有活动总数，不能计算它们逐日的增减；按渠道汇总也不包含渠道逐日数据。缺失、重复日期或不合法值不进行臆造比较。
- 现有录入和汇总流程可能把空白补成0。复盘显示的0可能是补零，不代表已确认的真实零；不能据此自动归因。零基数不计算百分比；营收不是利润。人工审核仍然必要。
- 现有前端读取同一 facts / hypotheses / suggestions / limitations 结构，无需新增页面。无模型密钥可用模板；模拟模型不能覆盖计算事实与必要建议。模型生成不能把推测当成已证实的效果。

## 给 a / b 的交接

- **b：** `MetricInput` 当前把空白补0，`analytics.trends` 按日期跨渠道汇总，仅含 impressions/revenue/spend；请保留指标未填与明确0、每指标覆盖条数/统计区间、增量与累计口径，提供按活动、商家、日期及渠道（必要时作品）筛选的观看、阅读、互动、咨询、订单/报名等逐日聚合。确认历史数据不能凭空还原后，再与 c 约定共享结构。
- **a：** 如要让商家选择可比日期/渠道，或在页面显示未填/累计快照，请与 b 共同设计录入及筛选流程；当前页面无需改动即可显示本次 facts 和建议。
- 本交接仅描述后续需求，不改变共享契约或其他成员代码。
