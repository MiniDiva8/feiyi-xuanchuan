# 抖音拍摄脚本 · Issue #17

本功能增强现有 `generate_asset(context)` 的 `kind=script`，沿用素材生成、编辑、审核和文字导出接口。默认30秒、五个镜头；不生成视频文件、不自动发布、不读取抖音账号数据，不需要新增抖音接口授权。

## 在现有页面使用

1. 在「资料档案」确认可营销使用的来源；在「产品课程」填写真实商品或课程、价格、库存/名额、地点、履约说明及外部购买/报名入口。
2. 在「活动工作室」选择对应商品销售或课程报名活动，将抖音列入活动渠道，生成并批准包含抖音的最新方案。
3. 在「传播素材」点「生成传播素材」，渠道选抖音、类型选「短视频脚本」。模型模式下可在「表达要求」提出优先展示哪条已确认资料等编排要求。
4. 现有素材正文直接显示标题、开场、五个镜头的时间/画面/口播/字幕、拍摄准备、发布文案、话题、行动提示及待补充项。模板有醒目标记，不会伪称模型结果。
5. 核实资料并真人试读。可以在原有「编辑」中修改正文，保存为新待审核版本；审核最新版本后使用「导出文本」。既有 HTML 导出接口也保留全部正文。修改来源或产品条件后，原有审批继续失效。

商品脚本展示实际商品外观、用途、购买及自提/交付条件；课程脚本展示实际体验内容、课程材料、场次与报名说明，不把活动日期当成课程时间。模板会优先选择与项目、活动和已批准渠道方向相关的已确认资料。口播只用完整且足够短的记录，不从多句内容中摘掉后续限定；长资料保留在拍摄资料区，超出资料预算时整体省略并提示，不挤成过长口播。选择方式与人工修订事实检查见 [事实核对与相关资料选择](FACTS-AND-SELECTION.md)。

## 输出及事实边界

- `body` 是页面展示、人工编辑、TXT/HTML 导出的完整正文。所有拍摄所需的重要内容均在此处，不需要前端读取新增字段。
- 保留 `content.duration_seconds: 30`、`shots: string[]`、`details: string`、`evidence: object[]`。新增 `storyboard`（每行 `candidate_id/start_second/end_second/visual/voiceover/subtitle`）、`hook`、`brief`、`preparation`、`caption`、`hashtags`、`cta`、`warnings`、`missing_information`。这些是 AI 返回内容的扩展，不改变共享接口或请求字段。
- 商品/课程和父级活动、方案须属于当前 workspace，项目绑定与活动目标须匹配。资料必须 `confirmed is True` 且 `usage_scope == marketing`，外商家、内部或未确认资料不会进入候选、正文或模型请求。与旧接口相同，未带 workspace_id 的记录依赖调用方先按已认证商家筛选；授权与来源快照校验继续由现有后端执行。
- 交易事实直接取商家配置；不存在的价格/库存不会补0，地点、履约、入口等缺项明确标「待补充」。库存为0或信息未齐时停止交易行动提示。有效的0元与缺失价格有区别。
- 资料区的设备、机位是拍摄建议，不表示商家已经拥有设备或素材授权。人物/场地/音乐授权及实际履约条件仍须商家核验。
- 入口只使用 `offering.conversion_url`，不臆造短链、购物车或挂链权限。发布前须人工确认地址有效及抖音允许的呈现方式；本功能不访问入口。
- 话题采用项目名称及普通手作/课程词，不补写未经核验的非遗级别、身份或荣誉。绝对效果承诺及缺来源身份会被拒绝。

## 模板与已有模型客户端

无 `MARKETING_AI_API_KEY` 时生成完整模板，正文标记「模板脚本｜未调用模型」。关键交易信息缺失时仍提供带待补充标记的拍摄草稿；原有产品 API 在销售/报名方案审批前要求有效关联项目、正库存/名额和有效入口，本次没有放宽这些门槛。

有密钥时仍使用 `engine._model`、现有 HTTPS 提供方、超时、JSON 解析与用量统计。模型根据活动、已批准方案和表达要求，选择有来源的镜头候选、调整中间镜头顺序和时长。为避免模型在正确详情之外另造价格、地点或身份，画面/口播/字幕必须逐字来自所选候选；模型不能自由改写这些事实文案。需要更自由的表达时，商家可在现有正文编辑器修订并重新审核。该限制是本轮模型编排设计，不代表开放式文案生成或真实模型质量已验收。

验证要求：恰好五镜头，开场与结尾位置固定，中间项目/来源/交易说明各一次；每镜头字段齐全、候选存在、事实文本匹配。时间是有限数字，从0连续到30秒，无间隙、重叠、倒序或越界；口播按每秒最多4个字/字母/数字保守校验。任何结构、事实匹配或时间校验失败都明确报错，模型超时/截断/错误 JSON 不会静默返回模板。后端持久化失败任务，页面可以按原流程查看和重试。

这套校验不替代商家来源真实性、拍摄授权或真人朗读验收，也不会检测人工编辑后正文中的所有经营事实与时长。

## 给 a / b 的交接

- **a：本次无需页面改动。** 素材卡、编辑器与文本导出均已使用 `body`。若以后增加分镜表格编辑器，可读取新增 `content.storyboard`，但需和 b 一起设计结构化修订与重新校验流程，不能在人工编辑正文后继续把旧分镜当成最新审核结果。
- **b：本次无需接口改动。** 现有 revise 只更新 `body/title`，保留原生成 `content`（包括旧分镜）；因此编辑后的正文是当前可见、可导出的权威文本，分镜结构是生成时的快照。本次不新增机器视频流程；以后若使用分镜自动剪辑，必须增加结构化修订、时长/事实校验和版本关联。缺失价格/入口在现有 OfferingInput 被拒绝，不需要为本功能放宽校验。
- 资料完整性提示、真实模型效果、抖音入口呈现能力不等同于已验证。保持草稿审核、人工发布和既有商家/活动隔离。
