# 给后端同伴：活动复盘需要区分未填和明确填零

## 用一场扎染课复现

1. 创建一场以报名为目标的活动。整场没有经营记录时，生成复盘应只提示店主先录入第一条数据。
2. 为这场课录入一条微信渠道的课后登记，填好日期、来源和归因，经营指标只提交咨询 10、报名 4、到场 3。请求里省略收入、退款和曝光，再生成复盘。
3. 当前接口给出报名/咨询 40%、到场/报名 75%，同时把未填项列为“收入：0元”“曝光：0”，还会计算“收入扣除退款为0元”。店主没有提供这些数值。

## 在哪里丢失了信息

- `services/api/app/schemas.py` 的 `MetricInput` 将未提交的数值字段默认成 0。手工录入保存完整模型，CSV 预检过滤空单元格后也经过这个模型。
- `services/api/app/metrics.py` 的 `analytics` 对所有数值字段求和，缺失字段按 0 累加。即使录入层保存了空白，汇总层也要保留“是否有观测值”。
- 网页录入表单 `apps/web/src/pages/Analytics.tsx` 会预填 0。若页面把未碰过的输入框作为 0 提交，后端无法单独还原用户意图，请前端同伴配合区分空白和手填 0。

## 建议一起验收

| 输入 | 应看到的结果 |
| --- | --- |
| 一条课程记录只填咨询 10、报名 4、到场 3 | 保留 40% 和 75%。收入、退款、曝光保持未记录，不生成缺少依据的净收入或比值。 |
| 店主明确录入收入 0 元 | 显示收入 0 元。退款留空时，收入扣除退款仍待补充。 |
| 同一活动两条记录，只有一条填了收入 | 若展示收入合计，应注明仅涵盖已填的那条记录。不能把另一条缺失值当作零来宣称全场总收入。 |
| 没有任何记录 | 继续返回记录数 0，由 AI 给出第一条录入提示。 |

建议由后端负责人 `donghaochen45-pixel` 核对手工录入、CSV 持久化、活动汇总及派生金额。所有记录都未填的指标，可以在传给 AI 的 `stats` 中省略该键；AI 已能处理缺键。部分记录有值时，请与 AI、前端约定覆盖情况的表达，再调整共享接口。历史记录中来源不明的 0 无法可靠还原，应保留原值并说明历史口径。
