# 文案事实核对与相关资料选择 · Issue #19

本次增强现有 `check_content`、方案/素材生成与资料上下文，没有新增 API、页面、依赖或外部检索服务。`checks` 仍为 `{level, message}` 数组，`content.evidence` 仍为原有来源 ID、标题和来源。已有脚本、复盘和版本审核机制保留。

## 现有页面如何使用

在「产品课程」维护当前项目的真实价格、库存/名额、地点与履约说明，在「资料档案」确认资料并允许营销使用。关联活动、批准方案后，照常在「传播素材」生成文案、海报文字或脚本；相关资料会结合项目、活动目标、已批准方案和表达要求选择，不再只看最早40条。

素材的现有检查提示会显示明确冲突及依据。例如商家配置售价128元、库存10件、仅支持自提，正文写「售价9.9元，库存100件，全国包邮」时，会分别提示价格、库存、履约冲突。错误后追加正确详情不能清除原错误。模型结果中的正文、标题及嵌套文字内容都会检查，存在明确冲突时生成明确失败，保留既有失败任务和重试流程，不回退模板假装成功。为保持已有提供方错误脱敏机制，生成失败仍使用现有通用错误信息；逐项依据由 `check_content` / 素材 `checks` 展示。

在原有「编辑」中修订正文并保存后，后端调用同一个检查函数。含明确冲突的新版本不能审核、导出；修正后重新审核即可沿用文字导出。历史版本保留。方案人工修订使用 JSON 文本输入时，检查实际字符串值，不把 JSON 的引号当成引用文字豁免。

## 核对依据与判断范围

- 经营数值依据为绑定当前活动的 `offering`，不会从其他商品或不明资料推定价格。商家自己的价格等配置也须人工核实，模块不访问电商、物流或真实渠道验证它们。
- 数值用十进制比较，支持0元、小数、千分位、全角数字、常见中文数量和「九块九／9元9角」等写法。缺字段或显式空值标为待补充，不补0；有歧义的「一百二」提示待核验，不猜120或102。
- 明确归属当前商品/课程的售价、库存/名额冲突为 `error`，包含原主张、项目名和配置依据。地点仅在可识别的不同城市或同路不同门牌等明确冲突时判错；地址别名、简写、房间等无法确定的情形给 `warning`。
- 履约规则覆盖明确的仅自提/仅邮寄、包邮与运费自理等常见冲突。其他履约安排、复杂套餐、条件优惠、各规格价格、地点别名需要人工确认，不能声称所有自然语言承诺都已验证。
- 日期、电话和时长不会仅因含数字而成为售价；「仅需30分钟」「剩余10秒」、折扣及尺寸单位优先按对应用途排除。预算、运费、收入等不是商品售价。没有足够明确的经营主张时，不强行提取所有数字。
- 历史价格、引用、其他商品、多商品/套餐、条件/估计和不明确的归属保留待核验提示，不武断判错。明确「口播/字幕/文案」中的主张仍检查；引用或模糊措辞也不是已通过事实认证。规则不能可靠理解所有隐喻、指代、否定和引用意图，仍可能漏检。
- 绝对效果承诺、非遗身份来源检查继续执行。生成和人工检查均先排除外商家、未确认、不可营销来源。若记录省略 `workspace_id`，仍依赖契约规定的后端按已认证商家筛选；本模块不替代授权层。

## 资料选择与预算

1. 先遍历全部资料，按商家、`confirmed is True`、`usage_scope == marketing` 过滤。禁止资料不会参与词频统计、排名或进入模型请求。
2. 对合格资料按中文相邻双字和英文词项匹配，不需要分词库、向量数据库、远程请求或付费调用。商品/课程名称及描述权重8，活动名称/受众/目标权重3，表达要求权重6，已批准方案权重4；未批准方案不作为选择依据。标题匹配加权，稀有匹配词权重较高。
3. 相关性排序后按 ID、标题、来源、原文稳定打破平分；输入顺序变化不改变选择。表达要求先参与完整匹配，再应用已有模型字段长度限制。
4. 排序后才限制最多40条、单条序列化记录4000字符、整个资料列表14000字符。记录连同来源整体保留或整体跳过；不会截取前4000字而丢失尾部限定条件。超长相关记录可能被省略，应由商家提供独立、完整且已确认的简短版本，不能自动摘要补造。
5. 内部 `selection_reason` 记录匹配维度和得分，素材现有 `checks` 的信息项展示选择数量及前三条资料的 ID/匹配依据。公共 evidence 保留原始 ID、标题、来源，模型不能另造引用；没有直接词项匹配的来源明确标出，不承诺排序等于语义理解。

生成上下文与事实检查分开：**本地事实检查使用全部合格来源的完整内容**，不受上述40条或字符预算影响。模型成功结果也传回原始上下文检查，不把裁剪后的模型上下文作为事实依据。价格等经营数值始终使用完整绑定项目；身份来源核对可使用未进入生成预算的完整来源，保留既有来源确认规则。

普通文案模板的前三条现在来自相关性排序。拍摄脚本继续把完整入选资料写入准备清单，口播/字幕只采用完整且能放进时长预算的短记录；不再从多句资料中单独摘出第一句，以免丢失后句限定。长记录保留在正文准备区或在预算省略提示中说明，不强塞进镜头。复盘的观察事实仍来自确定的统计计算，模型只提供假设和建议。

## 实际验证

全部新增测试使用虚构资料、模拟提供方及独立 SQLite，不读取真实商家数据、不使用真实密钥、不产生付费调用。

- 改动前在 PR #18 最新 head 实测：错误9.9元/100件/全国包邮只得到通用提示；模拟模型返回错误价格后又追加128元仍成功；第41条相关资料不进入正文或引用。原有 AI/后端/端到端基线87项、60个子测试通过。
- 新回归测试在原实现上先得到38项失败、7项通过；之后逐步扩充。额外先复现了时间/尺寸误判，以及摘句丢失后句限定两项失败。
- 最终完整回归命令：`python -m pytest tests/ai tests/backend tests/e2e -q -o faulthandler_timeout=30 --tb=short`：**147项通过、60个子测试通过，22.16秒**，1项既有 Starlette/httpx 弃用提示。新增54项参数展开单测、6项真实应用路由测试。
- 新测试覆盖正确/错误价格和数量、零元/小数、数字用途、缺资料/空值、多项目/模糊/历史/引用、模型隐藏字段冲突与成功、人工编辑、审核阻断/修正后导出、商家隔离、第41条以后资料、大量无关资料、稳定顺序、可追溯来源、完整限定条件及预算外检查依据。原有拍摄脚本、销售/报名/零记录复盘也参加回归。
- 未运行本轮真实浏览器、真实模型、线上服务或人工语义质量评估；API 测试通过不等于这些检查已通过。没有修改依赖以消除既有 Starlette/httpx 弃用警告。
