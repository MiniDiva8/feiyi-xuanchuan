# 非遗商家 AI 营销平台 — 产品设计

依据：用户提供的两张业务流程图，以及 2026-10-31 对现有项目目录的选择。用户授权补齐完整产品，本次继续在现有项目实施。保留协作基础设施，不修改成员身份、权限或自动合并规则。

## 目标与交付
让真实商家在持久化工作台完成：资料建档 → 产品/课程 → 活动 → 策划版本 → 商家确认 → 素材版本 → 商家审核 → 导出/发布登记 → 数据录入/导入 → 有证据的复盘 → 下一轮版本。中文桌面优先、适配移动端。

## 实现选择
采用 React/TypeScript/Vite 前端，FastAPI 后端，SQLAlchemy 数据层，SQLite 便捷本地启动、PostgreSQL 部署配置。方案选择由实施者根据现有三模块布局作出；不代表用户指定语言或框架。静态原型不能提供可靠的多商家隔离；直接集成电商支付和各渠道自动发布依赖尚未提供的资质，因此先支持已有购买/报名入口和可审计的手动发布。

## 数据与权限
用户、持久化会话、商家及成员角色；资料(来源/使用范围/确认状态)、文件、商品/课程、活动、不可变方案和素材版本、审核、发布、指标、导入批次、复盘、任务和审计。全部私有数据以服务端成员身份约束 merchant_id；浏览器传入商家 ID 不构成权限。密码使用带盐慢哈希，登录使用 HttpOnly Cookie，会话退出失效，写请求校验同源。API不暴露密钥或完整内部错误。

## 核心不变量
- 未确认或用途不符的资料不进入生成；公共模板显式标记。
- 方案批准后才生成素材；素材批准后才导出/登记发布；修订创建新版本，旧审批不能沿用。
- 发布记录固定关联方案版本、素材版本、渠道与真实作品链接，导出不等同发布。
- 商品和课程维护价格/库存或名额/履约/真实承接入口，本产品不处理支付。
- CSV先预检，事务提交，重复行不重复累计，保留来源和统计区间；未知归因单列。
- 复盘区分观察事实、原因假设、调整建议与数据不足；无成本或归因依据不宣称利润或营销贡献。
- 无模型配置时明确标为模板草稿；真实模型调用可配置、有限超时、错误可见、记录用量。不把模板标作真实 AI 结果。

## 外部条件
生产部署需要服务器/域名/HTTPS/备份、真实模型密钥和用量预算。自动渠道发布/订单同步需相应平台授权，本轮不伪造已接入状态。默认不推送、合并或部署。

## 验收
隔离攻击、退出会话、审核版本约束、重复导入、完整经营闭环、错误/空状态、持久化恢复、前端生产构建、浏览器端到端和既有协作测试。说明实际运行与未验证内容。
